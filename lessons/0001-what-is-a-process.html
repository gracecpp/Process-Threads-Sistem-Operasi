Lesson 1 Concept + tiny C

What is a process?

A program is a recipe. A process is the meal being cooked.

The one idea

A program is a file on your disk — dead bytes. When you run it, the operating system loads a copy of those bytes into memory, gives it a fresh workspace (its own stack, heap, and file descriptors) and starts executing it. That living, running thing is a process.

You can run the same program twice and get two processes. They don't share memory. They don't know about each other. Each has its own PID (process ID) — a number the kernel uses to keep them straight.

Mental model

Program : Process :: Recipe : Meal being cooked.
One recipe, many meals. Each meal has its own pan, its own ingredients, its own timer.

See it in C

Here's the smallest C program that makes the concept concrete. It asks the kernel for its own PID and prints it.

#include <stdio.h>
#include <unistd.h>   /* for getpid() */

int main(void) {
    printf("Hello. I am process %d.\n", getpid());
    return 0;
}

Compile and run it twice:

$ cc hello_pid.c -o hello_pid
$ ./hello_pid
Hello. I am process 48213.
$ ./hello_pid
Hello. I am process 48217.

Same program. Two runs. Two different PIDs. That's two processes. The kernel gave each one its own private memory and its own number. When each main() returned, the process ceased to exist. The program on disk was never touched.

What a process actually owns

When the OS creates a process for you, it hands it a little world:

  • Memory — its own address space. When your process reads memory at address 0x1000, it sees its byte there, not another process's.
  • File descriptors — the open files, sockets, and pipes it has. Usually 0 = stdin, 1 = stdout, 2 = stderr, to start.
  • A PID, and a parent PID (the process that launched it — your shell, usually).
  • At least one thread — the "main" thread that starts running main(). More on threads in Lesson 3.

Check yourself

You run ./hello_pid in one terminal, then ./hello_pid in another. How many processes exist?

Each invocation creates a fresh process with its own PID and its own memory. The program file is just a template.

If process A writes the number 42 to memory address 0x2000, and process B reads address 0x2000, what does B see?

Each process has its own address space. The same numeric address 0x2000 refers to a different physical byte in each process. That isolation is the whole point.

Try it yourself

  1. Save the program above as hello_pid.c.
  2. Compile: cc hello_pid.c -o hello_pid
  3. Run it three times. Note the PIDs.
  4. In another terminal, run ps while your program is running — you'll see it listed. (Add a sleep(30); before return so it stays alive long enough to catch.)
