Lesson 5 Concept + tiny C

What is a thread?

Same process. Same memory. Two lines of execution running through it.

Recall

Processes are isolated: each has its own memory. That's safe, but if two processes want to cooperate, they have to shout across a fence (pipes, sockets, shared memory segments).

Often you don't want a fence. You want multiple workers inside the same program, all reading and writing the same variables, working together on one job. That's a thread.

The one idea

A process is a container with:

  • An address space (code, heap, globals) — shared by everyone in the container.
  • A set of open files — shared.
  • One or more threads of execution, each with its own stack, its own program counter (which line it's on), its own CPU registers.

When people say "a program has one thread by default," they mean: when main() starts, the process has exactly one worker. You can hire more with pthread_create.

Mental model

Process = a workshop.
Threads = workers inside it.
The tools, the workbench, the parts bin (memory) are shared. But each worker has their own hands (stack, registers) and can be doing a different task at the same time.

See it in C

#include <stdio.h>
#include <pthread.h>

void *worker(void *arg) {
    char *name = (char *)arg;
    for (int i = 0; i < 3; i++)
        printf("  %s: step %d\n", name, i);
    return NULL;
}

int main(void) {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, worker, "A");
    pthread_create(&t2, NULL, worker, "B");
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("main: both done\n");
    return 0;
}

Compile with -pthread:

$ cc -pthread threads_demo.c -o threads_demo
$ ./threads_demo
  A: step 0
  B: step 0
  A: step 1
  B: step 1
  A: step 2
  B: step 2
main: both done

Two things to notice. First: the printfs are interleaved — that's two threads actually running in parallel (or rapidly time-sliced). Second: the interleaving order is not the same every run. Run it ten times; you'll see different orderings. This is the concurrency non-determinism we tasted with fork(), now much more in your face.

Two must-know functions

  • pthread_create(&handle, attr, fn, arg) — start a new thread. It will run fn(arg). The attr is usually NULL.
  • pthread_join(handle, &retval) — block until that thread finishes. Analogous to wait() for processes.

Check yourself

Thread A writes 42 to a global variable. What does thread B see when reading it?

Threads share the process's memory. Globals, heap, static data — one copy, visible to all threads. (Timing of when B sees it is a subtler question, coming in Lesson 6.)

Thread A dereferences a null pointer and segfaults. What happens to thread B?

Threads share a process. If one crashes the process, the whole process dies — and every thread with it. That's the flip side of shared memory.

Which one creates a new address space?

Only fork gives you a fresh address space. pthread_create adds a worker to the current one.

Try it yourself

  1. Compile and run threads_demo.c five times. Note how the interleaving of A and B differs.
  2. Bump the loop from 3 to 1000. Redirect output to a file and grep for how many A's came before the first B.
  3. Bonus: add a global int counter = 0; and, in worker, loop counter++ a million times. After both threads join, print counter. You expect 2 000 000. You will not get it. Save the surprising number — Lesson 6 explains why.
