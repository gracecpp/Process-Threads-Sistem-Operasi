Processes

#include <unistd.h>
#include <sys/wait.h>

pid_t rc = fork();          /* clone the process              */
if (rc < 0)      { /* error */ }
else if (rc == 0){ /* child : fork() returned 0            */ }
else             { /* parent: fork() returned child's PID  */ }

int status;
pid_t done = wait(&status);           /* block until any child exits */
if (WIFEXITED(status))
    int code = WEXITSTATUS(status);

char *argv[] = {"ls", "-l", NULL};
execvp("ls", argv);                    /* become another program     */
/* code here only runs if exec failed */

Rules

  • fork() returns twice — 0 in child, child PID in parent, -1 on error.
  • After fork, memory is copied but independent.
  • Every child must be wait()ed or it becomes a zombie.
  • If parent dies first, child is an orphan adopted by init (PID 1) — kernel handles cleanup.
  • exec…() keeps the same PID; replaces the program.
  • The Unix pattern: fork, then exec. That's how every command runs.

Threads

#include <pthread.h>
/* compile with: cc -pthread */

void *worker(void *arg) {
    /* do work */
    return NULL;
}

pthread_t t;
pthread_create(&t, NULL, worker, arg); /* start thread    */
pthread_join(t, NULL);                  /* wait for thread */

Rules

  • All threads in a process share memory (globals, heap).
  • Each thread has its own stack and its own registers.
  • If one thread crashes the process, all threads die.
  • Order of execution across threads is never guaranteed.

Mutex

pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

pthread_mutex_lock(&lock);
/* critical section: only one thread here at a time */
pthread_mutex_unlock(&lock);

Rules

  • A mutex protects data, not code. Every access to the shared data must take the same lock.
  • Keep critical sections short. No I/O inside if you can help it.
  • Always unlock. A forgotten unlock = permanent deadlock.
  • To avoid deadlock across multiple locks: always acquire them in the same global order.

Process vs Thread — at a glance

Common gotchas

  • Two forks in a row → 4 processes. Each fork doubles.
  • Code after successful exec() never runs.
  • counter++ is three CPU instructions — not atomic. Guard shared state.
  • volatile does not make things thread-safe.
  • Never assume ordering between two threads without an explicit sync primitive.
