Glossary

Definitions to keep consistent across every lesson.

Core

Program — a file on disk containing machine instructions (e.g. /bin/ls). Inert.

Process — a running instance of a program. Has its own memory, its own file descriptors, and at least one thread of execution. Identified by a PID.

Thread — an independent line of execution inside a process. Threads in the same process share memory (heap, globals) but each has its own stack and CPU registers.

PID — Process ID. A number the kernel assigns to each process.

Kernel — the core of the OS. The referee that decides which process/thread runs on the CPU next.

C / POSIX APIs

fork() — creates a new process by cloning the current one. Returns twice: 0 in the child, the child's PID in the parent.

exec…() — replaces the current process's program with a different one (keeps the PID).

wait() / waitpid() — the parent blocks until a child process exits, and collects its exit status.

getpid() / getppid() — this process's PID / this process's parent's PID.

pthread_create() — spawns a new thread inside the current process.

pthread_join() — waits for a thread to finish.

Concepts we'll meet later

Context switch — the kernel saving one running thread's state and loading another's.

Race condition — a bug where the outcome depends on the unpredictable ordering of threads.

Mutex — a lock that lets only one thread into a section of code at a time.
